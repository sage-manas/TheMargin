## Current phase

**Phase 2 is done except for the human playtest. Phase 3 is done for Chapter 1's needs, and Phase 4 (Chapter 1) is content-complete: all eight pages are built and the end card follows the finale.** Phase 4 isn't done until its playtest bar is met (≥ 70 % unaided completion, median 20–35 min). The Phase 2 prototype passes every automated test and has been browser-tested in Chromium, Firefox and WebKit. It has **not** been play-tested by people and is **not** deployed. The roadmap gates Phase 3 on that playtest (Risks R1, R2). The Phase 3 work so far covers word categories, crates, pressure plates, moving platforms, the eraser, ink and music. Chapter 1 pages 1.4 and 1.5 need the first three whatever the playtest finds, so that work is low-regret; the eraser and ink are Chapter 4 and 5 mechanics, built now as sandboxes so the framework's data model covers them.

**Phase 5 (web platform) has started alongside the playtest**, since it doesn't depend on Chapter 2. The site has its landing page, `/play` launcher, chapters and settings pages; the auth UI is next. Of the exit bar, Lighthouse is met (landing page: performance 98–100, accessibility 100) and `/play` launches in Chromium, Firefox (CI) and WebKit.

**Phase 6 (backend) meets its bar:** the API's integration tests pass against a real Postgres, and the offline→online sync and conflict tests pass, both as unit tests on the sync logic and end to end in Chromium and WebKit (Firefox on CI). The auth UI completes Phase 5 too. The Chapter 1 playtest is still the open Phase 4 item.

**Chapter 1 is being reworked before the project moves further (2026-11-12).** Playtest feedback: the theme and concept are strong, but the pixel art made props and scenes hard to understand, and play was repetitive (every page was "slide a room, carry HEAVY/OPEN/UP to a slot, reach a door"). Decisions and status: hand-inked vector art (ADR-0013); two new reader-hand mechanics, scene captions and close-ups (GDD §4.7, §4.8); pages 1.3–1.7 rebuilt around them, each with its own verb and goal, keeping 1.1, 1.2 and 1.8 (GDD §6). All three parts are built and tested; the Chapter 1 playtest now runs on the reworked chapter.

**Phase 8 (production readiness) has started with staging**, so the playtest can run from a URL with accounts on. The pipeline and runbook are in the repo (DEPLOY.md, ADR-0012). It hasn't deployed yet: it needs the one-time account setup (Neon, Fly.io, Vercel and GitHub secrets).

- **Phase 3 (2026-11-06): the eraser (GDD §4.3).**
  - **Pencil sketches** (`sketches` in panel data): graphite lines, solid while drawn. Ink is never a sketch, so ink can't be erased. A sketch can start `erased` (a smudge).
  - **The eraser is found, not given:** an `eraser` object Nib walks into. It becomes an ability (`progress.abilities: ["eraser"]`), so it is never drawn again on any page.
  - **X erases** the pencil line in reach, which removes its collision and leaves its crumbs; X on a smudge draws it back for those crumbs. The prompt explains refusals: ERASER FULL, NEEDS N CRUMBS, SOMETHING IS IN THE WAY (never over Nib or a crate). Crumbs show as pips above Nib.
  - **Crumbs are derived, never saved:** each sketch's difference from how it was drawn. The eraser holds `eraser_holds` (default 3), so you can't erase more than you can put back. Saves store `pages.<id>.sketches` (id → drawn, optional, so older v1 saves still load); a save implying an impossible crumb count resets that page's sketches.

  - Sandbox page `sb_eraser` (`-- --page=sb_eraser`): rub out a pencil wall (which fills the 2-crumb eraser), draw a step back to make room, erase the shelf so its crate drops on a plate and opens the door, and draw the second step to reach it. 6 headless tests; page validation checks sketch bounds, unique ids and crumb costs within capacity; the contracts schema and a contract test cover `sketches`.

- **Phase 6 (2026-11-07): the API (`apps/api`, backlog 28; ADR-0011).** PR #10 (the site) merged with green CI, including Firefox and Lighthouse.
  - **NestJS 12 (ESM), compiled with SWC; Prisma 7 + `@prisma/adapter-pg`; PostgreSQL.** The schema follows DATABASE.md (citext emails, cascading user-owned rows, 64 KB save CHECK, seeded chapters and achievements from `packages/contracts`). The initial migration is committed and CI checks it matches the schema.
  - **Auth (ADR-0007, TDD §6):** register, login, logout and session, with Argon2id passwords (OWASP minimum cost). Sessions are 256-bit tokens in an HttpOnly SameSite=Lax cookie, stored as SHA-256, with a 30-day expiry that slides at most once a day. Logins take the same time and give the same answer for an unknown email and a wrong password. CSRF uses a double submit (header must equal the HttpOnly `tm_csrf` cookie, token from `GET /auth/session`) plus an Origin allowlist, on every state-changing request including login. Rate limits: register 5/min, login 10/min, others 120/min per IP. Helmet, strict CORS with credentials, a body limit sized for one save, and one error envelope for everything (internals logged, never sent).
  - **Saves:** `GET`/`PUT /saves/main` with an atomic compare-and-swap on the cloud revision (of racing writes from the same base exactly one wins; the rest get 409 with the server's copy), 422 for a save from a newer game, size and schema validation, and `PUT /saves/backup-:ts` keeping the newest 5 conflict losers.
  - **Progression, achievements, settings, profile:** chapters lock until released and reached; completing is validated, idempotent and awards `CH01_COMPLETE`, which clients can't unlock themselves. Achievement unlocks are idempotent. Settings default until set and are validated against `SettingsSchema`. `PATCH /me/profile`. `GET /health` pings the database.
  - **Fixed before it shipped:** a failed login would have revoked the browser's existing session (it now revokes only after success). Prisma's `pg` adapter read `timestamptz` 5.5 h off under a non-UTC server timezone, which made expired sessions valid. Connections are now pinned to UTC, and the test database runs in IST so this can't come back unnoticed.
  - **Contracts:** API request and response schemas (`api.ts`), the error codes, and the achievement catalogue (checked against the codes the game emits).
  - 28 integration tests (`pnpm api:test`), in a CI job with a Postgres 17 service. `pnpm db:up` starts Postgres locally. Test scripts now pass `--experimental-strip-types`, so Node 22.12–22.17 runs them too.

- **Phase 6 (2026-11-07): accounts and cloud sync in the site (backlog 29; completes the Phase 5 auth UI).** Stacked on PR #11 (the API).
  - **Auth UI:** `/account` (sign in, create account, sign out) and the signed-in name in the header. Errors are in plain words, including when the accounts server is unreachable (play still works). The site reaches the API at same-origin `/v1`, proxied to `API_DEV_ORIGIN` locally, so its cookies are the site's and need no CORS. `ApiClient` is Zod-free (every page shows the header) and refreshes a stale CSRF token once.
  - **Save sync (`SaveSync`, TDD §4.3):** on `/play` the browser's save is reconciled with the cloud, and each local save is pushed on the cloud revision it was based on. Offline, it retries from 2 s doubling to 5 min, or immediately on `online`/`visibilitychange`, and play made offline costs one push. Conflicts are resolved with `resolveConflict`: the loser goes to a cloud backup, and if the cloud wins the game gets `LOAD_CLOUD_SAVE`. Sync state survives reloads, so a save made offline before closing the tab syncs on the next visit. A different account on the same browser starts from scratch. A 401 stops syncing; invalid saves don't retry. The launcher's toolbar says where progress is: saved online, offline (will sync), or signed out.
  - **Found while wiring it:** `LOAD_CLOUD_SAVE` queued before the game started would have been dropped, because the bridge autoload drains its inbox before the main scene connects. The site now waits for `GAME_READY`.
  - **Outbox:** `CHAPTER_COMPLETED` and `ACHIEVEMENT_UNLOCKED` are forwarded to the API through a persisted queue. Settings changes are pushed after a debounce; cloud settings fill a browser that has none.
  - API rate limits can now be set from the environment (`RATE_LIMIT_*`), for test setups that share one IP.
  - Tests: 11 sync unit tests against an in-memory cloud with the API's compare-and-swap rules (first upload, new device, offline backoff and one push on reconnect, offline across a reload, both conflict directions, stale device, identical saves in another key order, account switch, 401/5xx/422). 3 e2e tests against the real site, API and game: a second browser continues from the account's save; offline play syncs once back online; a conflict with more progress elsewhere loads the cloud save into the running game. ## Known issues and limitations

1. The `localStorage` mirror is unavailable when a browser blocks site storage (some private modes). The game still plays, with the old IndexedDB-only behaviour.
2. Placeholder-grade art and synthesised audio. Only Chapter 1 has music; the title screen plays only room tone. The music isn't cached between sessions, so it is rebuilt on every boot (caching the rendered loop in `user://` is a possible optimisation).
3. Only Chapter 1 is in the story; the end card follows page 1.8. The browser e2e plays pages 1.1–1.2 and 1.8 (from a seeded save); 1.3–1.7 are covered by headless real-physics solutions only.
4. A crate can't carry another crate (a rising crate stops under one), so stacked crates don't add weight to a plate. LIGHT has no effect on panels yet. Since the rework, crates, plates and platforms appear only in sandboxes (kept for later chapters).
5. Captions that hold words can't be rewritten by story actions (validated by `test_pages`).
6. The sandbox page can only be opened from the command line or editor, not from the web build.
7. The 38 MB `index.wasm` is the stock engine template (≈9 MB with Brotli). A custom slim template is a Phase 8 optimisation.
8. CI was green on PR #2 and its merge to `main` (2026-11-06: Godot tests, web export, contracts, Chromium + Firefox on Linux). CI was also green on PR #3 (eraser). Firefox has not run against the ink changes yet; it runs on their PR. Headless Firefox on the GPU-less runner has no WebGL2, so CI runs Firefox headed under `xvfb-run` (`E2E_HEADED=1`).
9. The workflow's actions (`checkout`, `setup-node`, `pnpm/action-setup`, `upload/download-artifact`, all v4) still target the deprecated Node 20 runtime; bumping them is a small follow-up.
10. The eraser targets only whole sketches (no partial rubbing), and sketches are axis-aligned rects. Erasing a crate's support while Nib stands underneath leaves the crate hovering above Nib until Nib steps away (crates never crush Nib). The "underdrawing revealed by erasing" (GDD §4.3) isn't built yet.
11. **Only the first bold word in a narrator caption can be reached.** Every word in a caption shares the caption's `reach_at` point, and the nearest-slot pick keeps the first on a tie, so in `sb_mechanics` ("CRATES GO *UP*. UNTIL THEY *STOP*.") STOP can never be targeted. Story pages so far have one word per caption; `sb_platforms` uses two captions. A fix needs a design call (per-word reach points, or cycling targets).
12. Scene cards and close-ups are new verbs taught by a margin hint on their first page (1.3, 1.4). Watch in the playtest whether players find them unaided, and whether 1.5's two-card order is fair.
13. A scene card's corner sits over the panel's top-right; page layouts keep that corner clear, but nothing validates it yet.
14. The 1.8 erasure takes about 2 s and doesn't lock Nib; walking back into the sealed border during it is harmless. An erased panel can't be restored (no story action undoes it).
15. The site has no accounts yet: the auth UI is the next Phase 5 step, and it needs the Phase 6 API to do anything. Progress shown on the site is this browser's only.
16. `/play` and `/settings` ship Zod (about 60 KB) to validate bridge messages and settings; the landing and chapters pages don't.
17. A game build on a different origin from the site (the CDN) needs CORS headers on its files. Only same-origin `/game` has been tested.
18. `GAME_ERROR` messages are logged by the launcher but not shown to the player.
19. OpenAPI docs at `/v1/docs` are deferred. There's no password reset or email verification yet (no email provider), and no account deletion endpoint (the database cascades are ready).
20. The API's `dist/` needs the workspace's `packages/contracts` at runtime (ADR-0011), which shapes the Phase 8 container build. Expired sessions are swept daily by an in-process timer, so with several instances each one sweeps.
21. On a shared browser, signing in to a second account can upload the first account's local save to it when the second account has no cloud save (the local save isn't tagged with an owner). Signing out doesn't clear the local save.
22. In WebKit at ×1 page scale, a Playwright drag lands one 8 px grid step short (fine at ×2, which the e2e uses). Check whether real Safari at ×1 does the same.
23. Settings conflicts are last-writer-wins, and cloud settings are pulled only into a browser with no settings of its own.
24. Staging isn't live until the one-time setup in DEPLOY.md is done. The API image has only been built on CI (Docker wasn't running on the development machine).
25. The API trusts two proxy hops for client IPs, so a direct caller of the Fly hostname can forge `X-Forwarded-For` and dodge rate limits (DEPLOY.md, known gaps). For the Phase 8 security review.
